# DIANO Backend Gaps & Contract Discrepancies (`BACKEND_GAPS.md`)

**Updated:** 2026-11-22 (Post BG-06, BG-26, BG-27 Resolution Sync)  
**Purpose:** Authoritative registry of backend endpoints, fields, or permissions that are absent or differ between documentation (`FRONTEND_HANDOFF.md` / `API_CONTRACT.md` / `ANALYTICS_DEFINITIONS.md`) and the live `diano-server` implementation (`openapi.json` 258 operations + `src/`).

> **Frontend Rule:** Never invent endpoints, fake data, or simulate unsupported operations. Every gap listed below must either use the documented real alternative endpoint or render an honest `"Not available yet"` / read-only state in `diano-admin`.

## 2. Active / Open Backend Gaps (Render Honest Frontend Fallback)

| # | Feature / Screen Affected | Open Gap / Alternative Endpoint | Frontend Handling Strategy |
| :--- | :--- | :--- | :--- |
| **BG-03** | **Active Device Sessions List** (`/admin/settings`, `/admin/staff/:id`) | No active session query endpoint (`GET /api/v1/auth/sessions`). `GET /api/v1/auth/login-history` and revocation endpoints exist. | Show recent login history via `GET /api/v1/auth/login-history` and provide `"Revoke All Sessions"` via `POST /api/v1/auth/logout-all` / `POST /api/v1/users/:id/revoke-sessions`. |
| **BG-07** | **Reports Export:** Standalone Products, Payments & Expenses (`/admin/reports`) | Standalone file export endpoints do not exist; `reports.routes.ts` supports `POST /api/v1/admin/reports/{orders,sales,inventory,customers,financial}`. | Enable CSV/XLSX/PDF export for the 5 supported domains; mark standalone `products`, `payments`, and `expenses` exports as `"Included in Financial/Inventory/Sales reports — standalone export not available"`. |
| **BG-08** | **Category Reorder Method & Path** (`/admin/categories`) | `PUT /api/v1/categories/reorder` is exposed (not `PATCH`). | Use `PUT /api/v1/categories/reorder`. |
| **BG-09** | **Abandoned Checkout Recovery Path** (`/admin/abandoned-checkouts`) | `POST /api/v1/abandoned-checkouts/:id/recovery` is exposed (not `/recover`). | Use `POST /api/v1/abandoned-checkouts/:id/recovery`. |
| **BG-12** | **Unseeded System Roles in `seed.ts`** | `inventory-manager` and `support-staff` role rows are not seeded by default unless assigned via Roles & Permissions. | Documented in Roles & Permissions screen so custom/staff roles can be assigned permissions via `PUT /api/v1/roles/:id/permissions`. |
| **BG-13** | **KPI Card Shape (`/admin/analytics/overview`)** | `analytics.types.ts` returns `{ current, previous, change, percent, trend: 'UP'\|'DOWN'\|'FLAT'\|'NONE', unit, note }`. | Normalize KPI card shape in frontend adapter. Render `"—"` when `percent` is `null`. |
| **BG-14** | **Analytics Numbers vs Decimal Strings** | Mixed: `number` in analytics aggregations, Decimal `string`s in transactional models (`Order`, `ProductVariant`, etc.). | Shared `MoneyText` / `formatBdt()` utility safely formats `string \| number` using `Intl.NumberFormat('en-BD')` without floating-point math in the UI. |
| **BG-15** | **Socket.IO Event Names** | Real event names emitted by backend: `order:new`, `order:status`, `payment:status`, `stock:low`, `checkout:abandoned`, `fraud:review`, `notification:new`. | Listen strictly to the 7 real backend Socket.IO events. |
| **BG-16** | **Fraud Risk Tiers** | Prisma `FraudRiskLevel` has only `LOW`, `MEDIUM`, `HIGH`. | Render badges and filters strictly for `LOW`, `MEDIUM`, and `HIGH`. |
| **BG-17** | **Notifications Unread Count** (`/admin`, topbar bell) | Dedicated standalone `/unread-count` endpoint does not exist; however, `GET /api/v1/notifications` returns `pagination.unreadCount` directly on its payload, and the event bus emits `notification:new`. | Topbar `NotificationBell` reads real `pagination.unreadCount` from `GET /api/v1/notifications` and updates badge instantly upon debounced `notification:new` socket events. |
| **BG-18** | **Account Lockout Structured Retry Info** (`POST /api/v1/auth/admin/login`) | Backend lockout response returns HTTP 403 with lockout duration embedded strictly inside string `message` (`"Try again in X minute(s)."`), without a structured `retryAfterSeconds` or `retryAfterMinutes` number field. | Frontend `formatLockoutMessage` uses a regex fail-safe extractor, defaulting to a clean generic message if parsing fails. |
| **BG-19** | **Product Concurrency & Versioning** (`PATCH /api/v1/products/:id`) | Product updates use last-write-wins semantics without optimistic concurrency locking or version checks (`version` / `updatedAt` guard). | Frontend uses dirty form guards and disables double submissions to mitigate race conditions. |
| **BG-20** | **Product Create & Media Slots Sequence** (`POST /products` & `POST /products/:id/images/*`) | Product creation requires at least one variant upfront but image slot uploads require an existing `productId`. | Frontend provides a seamless two-step flow: create product with initial variants and pricing first, then immediately unlocks the media slots tab on the created product. |
| **BG-21** | **Standalone Warehouses List Endpoint** (`/admin/inventory`, `/admin/purchases`) | No standalone `GET /api/v1/warehouses` endpoint exists. Warehouse records are embedded inside `InventoryEntity`, `PurchaseOrderEntity`, and `StockAuditEntity`. | Frontend extracts unique warehouses from inventory query cache with graceful fallback to manual ID entry (e.g. default `Central Warehouse Dhaka`). |
| **BG-24** | **Order REFUNDED Status Transition is Label-Only** (`PATCH /api/v1/orders/:id/status`) | In `orders.service.ts`, transitioning an order to `REFUNDED` only updates `Order.status = 'REFUNDED'` and appends history. It does not initiate a payment gateway refund (SSLCOMMERZ) or update `paymentStatus`. | Per system decision, one-click `REFUNDED` transition button is removed from `ORDER_TRANSITION_TABLE['RETURNED']`. Actual gateway refunds must be issued via the dedicated refunds module (`/admin/refunds`). |
| **BG-25** | **Manual SSLCOMMERZ Payment Re-verify Admin Endpoint Missing** (`POST /api/v1/admin/payments/:id/reverify`) | In `payments.routes.ts`, admin payment routes only expose `GET /`, `GET /:id`, `POST /:id/mark-cod-collected`, and `POST /:id/refund`. There is no admin endpoint to manually trigger a query or re-verify against the SSLCOMMERZ gateway for an unconfirmed or pending transaction. Background reconciliation runs via cron (`internal-jobs.service.ts`), but cannot be triggered per-payment from admin UI. | Frontend surfaces an honest informational status explaining automatic callback/IPN capture and cron reconciliation, marking manual single-transaction re-verify as pending backend API addition. |
| **BG-28** | **Homepage Sections / Custom Block Builder Missing** (`/admin/cms/homepage-sections`) | `diano-server` does not expose any routes or DB models for custom homepage section builders or landing block layouts. Promotional layout is handled via `BannerPlacement` (`HOME_HERO`, `HOME_SECONDARY`) and public featured products (`GET /api/v1/products/featured`). | Frontend renders banner carousels and placements directly; custom section builder is documented as absent in backend. |
| **BG-29** | **Standalone Media Library / Asset Browser Missing** (`/admin/media`, `POST /api/v1/media/upload`) | No centralized media repository exists. Media uploads are strictly domain-specific: `POST /settings/logo`, `POST /settings/favicon`, `POST /categories/:id/image`, `POST /products/:id/images/*`. | Frontend uses direct Cloudinary URLs and domain-specific upload endpoints. |
| **BG-30** | **Notification & Email Template Customization Endpoint Missing** (`/admin/notifications/templates`) | Backend provides notification delivery outbox logs and retry (`/admin/notifications`), but exposes no endpoints to customize notification or email templates. | Documented in CMS support table as not supported by backend. |
| **BG-31** | **Dedicated Security Events Feed Endpoint Missing** (`/admin/security-events`, `GET /api/v1/admin/security-events`) | `diano-server` does not provide a dedicated `/security-events` router or endpoint. Security-relevant activities (admin logins, session revocations, password changes, privilege changes) are recorded directly into the general `AuditLog` table queried via `GET /api/v1/admin/audit-logs`. | Frontend surfaces security events through the Audit Logs module (`/admin/audit-logs?tab=security`) by querying `GET /api/v1/admin/audit-logs` and filtering on auth/security action types (`AUTH_*`, `USER_PASSWORD_*`, `ROLE_*`). |
| **BG-32** | **Order Entity Does Not Return Computed `maxRefundable`** (`GET /api/v1/admin/orders/:id`) | While `refunds.service.ts` calculates remaining refundable balances atomically before disbursing, `OrderEntity` returned by `GET /admin/orders/:id` does not include an explicit `maxRefundable` field. | Frontend adheres to rule *"show remaining refundable amount only if returned by API"*, omitting client-side balance guesses and letting the user specify desired refund or default to full remaining balance, backed by backend validation. |
